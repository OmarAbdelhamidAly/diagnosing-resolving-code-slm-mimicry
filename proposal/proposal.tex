\begin{researchbox}[title={Executive Abstract}]
Small Language Models (SLMs) in the 1--3B parameter regime offer vital cost, latency, and data privacy advantages for telecommunications automation, edge code generation, and self-healing infrastructure across Orange Innovation. However, recent empirical findings demonstrate a critical vulnerability: while these models attain high accuracy on verbatim textbook benchmarks (e.g., HumanEval), their performance experiences catastrophic collapse when faced with semantically identical problems subject to superficial lexical, structural, or narrative perturbations.

This proposal formulates a rigorous, two-stage scientific framework to probe and resolve this failure mode:
\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{The Diagnostic Reduction Ladder (L0--L5):} Mapping directly to peer-reviewed benchmarks on Hugging Face (\textbf{EvoEval}, EMNLP 2024), we establish six progressive transformation levels to quantify the exact \emph{collapse point} ($\ell^*$) and diagnose failure distributions across on-path, off-path, and template-memorization errors.
  \item \textbf{Prioritized Multi-Arm Mitigation Framework:} Rather than confining our exploration to a single technique, we formulate and empirically evaluate four prioritized mitigation arms:
  \begin{itemize}
    \item \textbf{Arm 1 (Priority 1 — Primary Mitigation):} Invariance-Regularized Policy Optimization (\textbf{Inv-GRPO}), introducing paired cross-perturbation sampling and consistency rewards ($\mathcal{R}_{\text{consistency}}$) with zero inference latency overhead.
    \item \textbf{Arm 2 (Priority 2 — SFT Distillation):} Contrastive Thought-Template SFT (\textbf{Contrastive-SFT}), fine-tuning on positive Chain-of-Thought (CoT) paired with negative template rejection traces.
    \item \textbf{Arm 3 (Priority 3 — Structural Syntax):} AST-Guided Policy Optimization (\textbf{AST-RL}), incorporating tree-edit similarity rewards (\texttt{simAST}).
    \item \textbf{Arm 4 (Priority 4 — Process Verification):} Stepwise Execution-Gated RLVR (\textbf{Step-RLVR}) with intermediate contract checking.
  \end{itemize}
\end{enumerate}

We provide a structured 12-week (3-month) execution timeline, a clean architectural blueprint, VRAM-optimized training protocols on commodity edge hardware (RTX 3070 8GB), and actionable deployment guidelines for Orange Innovation.
\end{researchbox}

\section{Introduction \& Motivation}
%============================================================

The integration of Small Language Models (SLMs) into autonomous network management, infrastructure-as-code synthesis, and software repair pipelines requires predictable algorithmic generalization. Unlike conversational assistants where stylistic variance is tolerable, code synthesis in enterprise environments demands strict mathematical and logical invariance.

\subsection{The Reasoning vs.\ Memorisation Crisis in Code Models}

Recent studies~\cite{gsm_symbolic, memorize_or_generalize, evoeval} reveal that high benchmark scores often mask superficial pattern matching:
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Lexical Vulnerability:} Renaming variables or modifying function signatures degrades pass rates by up to 35\%~\cite{gsm_symbolic}.
  \item \textbf{Narrative Sensitivity:} Embedding identical algorithmic tasks within domain-specific stories (e.g., routing packet allocation rather than array indexing) causes over 40\% degradation~\cite{evoeval}.
  \item \textbf{The Supervised Fine-Tuning Paradox:} Standard SFT on Chain-of-Thought (CoT) data often amplifies \emph{format mimicry} and template memorization, increasing superficial confidence while reducing resilience to out-of-distribution shifts~\cite{memorize_or_generalize}.
\end{itemize}

\subsection{Relevance to Orange Innovation Infrastructure}

For Orange Innovation Labs, deploying models that rely on memorized templates introduces substantial operational risk:
\begin{enumerate}[leftmargin=2cm]
  \item \textbf{Network Orchestration:} Automated scripts generated for novel edge topologies must satisfy invariant routing constraints regardless of variable naming or prompt phrasing.
  \item \textbf{Zero-Day Bug Remediation:} Autorepair agents must synthesize patches based on underlying control flow rather than replaying outdated patch templates.
  \item \textbf{Edge Compute Constraints:} Enterprise deployments require parameter-efficient SLMs ($\le 2\text{B}$ parameters) that maximize reasoning density per parameter without relying on multi-billion parameter cloud APIs.
\end{enumerate}

\section{Why the Code Domain? Rationale Over General NLP}
%============================================================

A central question in this research is: \emph{Why select programmatic code synthesis rather than open-ended natural language generation or general mathematical word problems?}

\begin{domainbox}[title={\faCode\ Foundational Rationale: Why Code is the Optimal Scientific Laboratory}]
\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{Deterministic, Objective Verification (Zero LLM-Judge Bias):}
  In natural language reasoning, evaluating intermediate reasoning steps requires subjective human grading or error-prone LLM-as-a-judge heuristics. In contrast, code execution yields binary, deterministic, and sandbox-verifiable ground truth ($0/1$ pass/fail against unit tests) with microsecond precision.
  
  \item \textbf{Strict Semantic Equivalence vs.\ Surface Syntax (AST Isomorphism):}
  In natural language, paraphrasing alters meaning subtly. In code, modifying variable names, reordering independent statements, or introducing helper functions preserves the \textbf{exact operational semantics and Abstract Syntax Tree (AST) invariants} while completely transforming the surface token distribution. This provides a clean mathematical baseline to isolate reasoning from memorization.
  
  \item \textbf{Combinatorial State Space \& Edge Case Fragility:}
  Code synthesis requires multi-step state tracking, boundary condition handling, and algorithmic invariant maintenance. A model relying on shortcut pattern matching will fail catastrophically on edge cases, making shortcut learning immediately observable and measurable.
  
  \item \textbf{Direct Enterprise Impact on Orange Product Stack:}
  Validating and hardening code SLMs provides direct deployment value to Orange Innovation's network automation, self-healing systems, and internal developer tools.
\end{enumerate}
\end{domainbox}

\section{Literature Taxonomy \& Research Landscape (2024--2026)}
%============================================================

To establish a comprehensive academic foundation, we synthesize recent literature across five foundational schools:

\subsection{1. Diagnostic Benchmarks \& Generalization Probing}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{EvoEval (EMNLP 2024)~\cite{evoeval}:} Created five semantic perturbation dimensions for HumanEval, establishing that 57 state-of-the-art LLMs suffer an average 38--40\% degradation across subtle, creative, and combined transformations.
  \item \textbf{GSM-Symbolic (ICLR 2025)~\cite{gsm_symbolic}:} Demonstrated that non-functional prompt variations induce catastrophic reasoning collapse in math models.
  \item \textbf{Memorize or Generalize? (arXiv:2503.02296, 2025)~\cite{memorize_or_generalize}:} Defined the Memorisation Risk Index (MRI) and revealed that standard SFT exacerbates template memorization while RLVR promotes invariant reasoning.
  \item \textbf{LiveCodeBench (arXiv:2403.07974, 2024)~\cite{livecodebench}:} Provides continuously updated, contamination-free programming problems used as our temporal control group.
  \item \textbf{CRUXEval (ICML 2024)~\cite{cruxeval}:} Evaluated code reasoning via input/output execution prediction, proving that code understanding lags far behind code generation.
\end{itemize}

\subsection{2. Invariance \& Perturbation-Aware Reinforcement Learning}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{CLARity (2025)~\cite{clarity_rl}:} Formulated consistency-aware reinforcement learning rewards that penalise contradictory reasoning paths across semantically equivalent queries.
  \item \textbf{LoPE (2025)~\cite{lope_perturbation}:} Demonstrated that injecting task-irrelevant prompt perturbations during RL training prevents policy overfitting and breaks shortcut optimization.
  \item \textbf{Break-The-Chain (2025)~\cite{break_the_chain}:} Investigated Chain-of-Thought robustness, showing that CoT traces often break under semantic reframing.
\end{itemize}

\subsection{3. Contrastive Learning \& Policy Optimization}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{ReCode (2025)~\cite{recode_contrastive}:} Designed contrastive reasoning-process rewards distinguishing logical derivations from shortcut derivations.
  \item \textbf{CLIPO (2025)~\cite{clipo_rl}:} Integrated contrastive trajectory clustering directly into policy gradient updates to stabilize RL exploration.
  \item \textbf{SuperCorrect (2024)~\cite{supercorrect}:} Distilled hierarchical thought templates and negative correction traces for autonomous error recovery.
\end{itemize}

\subsection{4. Information Bottleneck \& Representation Regularization}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{IB-FT (2024)~\cite{ibft_memorization}:} Formulated an Information Bottleneck loss penalty on hidden representations to compress superficial prompt features and retain invariant algorithmic logic.
  \item \textbf{IBRO (2025)~\cite{ibro_rlvr}:} Applied Information Bottleneck principles directly to RLVR, ensuring reasoning traces remain informative without memorized noise.
\end{itemize}

\subsection{5. Process Reward Models \& Structural AST Invariance}
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{CodePRM~\cite{codeprm} \& ExecVerify~\cite{execverify}:} Explored step-level and execution-trace rewards to prevent outcome reward hacking.
  \item \textbf{TreeDiff~\cite{treediff} \& VeriSeek~\cite{veriseek}:} Enforced Abstract Syntax Tree (AST) similarity rewards (\texttt{simAST}) to ensure syntax robustness.
\end{itemize}

\subsection{Arm 1 (Priority 1 — Primary): Invariance-Regularized GRPO (Inv-GRPO)}

During training, Inv-GRPO feeds paired inputs $(x, x')$ representing logically equivalent variants (e.g., $x \in L_0$ and $x' \in L_2$):
\[
\mathcal{R}_{\text{total}}(y_i, y'_i) = \mathcal{R}_{\text{exec}}(y_i) + \mathcal{R}_{\text{exec}}(y'_i) + \lambda \cdot \mathcal{R}_{\text{consistency}}(y_i, y'_i) - \gamma \cdot \mathcal{P}_{\text{template}}
\]
where:
\begin{itemize}
  \item $\mathcal{R}_{\text{exec}}(y) \in [0, 1]$ is the execution pass rate across the unit-test suite.
  \item $\mathcal{R}_{\text{consistency}}(y_i, y'_i) = \mathbb{I}(\mathcal{R}_{\text{exec}}(y_i) = 1 \land \mathcal{R}_{\text{exec}}(y'_i) = 1)$ enforces joint solution consistency with zero inference latency overhead.
  \item $\mathcal{P}_{\text{template}}$ penalizes boilerplate outputs exhibiting uncalled classic template signatures.
\end{itemize}

The joint group advantage is computed over paired rollouts:
\[
\hat{A}_{i} = \frac{\mathcal{R}_{\text{total}}(y_i, y'_i) - \mu_{\mathcal{R}}}{\sigma_{\mathcal{R}} + \epsilon}
\]

\subsection{Arm 2 (Priority 2): Contrastive Thought-Template SFT}

Inspired by SuperCorrect~\cite{supercorrect}, this arm augments SFT training data with negative shortcut examples, training the student model via cross-entropy loss to explicitly reject memorized templates:
\[
\mathcal{L}_{\text{Contrastive}} = -\sum_{t=1}^{T} \log P_\theta(y_t^+ \mid x, y_{<t}^+) + \alpha \max \left( 0, \log P_\theta(y^- \mid x) - \log P_\theta(y^+ \mid x) + m \right)
\]

\subsection{Arm 3 (Priority 3): AST-Guided Structural Policy Optimization}

This arm integrates a deterministic syntax parser into the RL reward loop. For any generated code $y$, we compute the tree-edit distance against the reference canonical AST:
\[
\mathcal{R}_{\text{AST}}(y) = \exp \left( - \alpha \cdot \text{TreeDist}(\text{AST}(y), \text{AST}(y^*)) \right)
\]

\subsection{Arm 4 (Priority 4): Stepwise Execution-Gated RLVR}

Building upon CodePRM~\cite{codeprm} and ExecVerify~\cite{execverify}, this arm checks pre- and post-conditions of sub-functions during sandbox execution, awarding partial reward credits for correct algorithmic sub-goals in complex L4/L5 problems.
