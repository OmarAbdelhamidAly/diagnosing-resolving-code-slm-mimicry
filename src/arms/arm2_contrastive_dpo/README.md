## Overview

Arm 2 addresses mimicry through **offline preference alignment**: we explicitly teach the model to *prefer* solutions that demonstrate algorithmic reasoning over solutions that mimic the memorized canonical L0 template.

The training corpus consists of **(prompt, chosen, rejected)** triplets where:
- `prompt` = a transformed version of the problem (L2/L3/L4 framing)  
- `chosen` = a structurally correct solution with reasoning trace  
- `rejected` = the verbatim L0 canonical solution that **fails** under the transformed problem  

This directly trains the model to *detect and reject* the mimicry pattern.

## The Core Insight: Hard Negative Construction

Vanilla SFT (M2) teaches *what correct code looks like* without ever showing the model *what incorrect-but-plausible code looks like*. The model never learns to distinguish between:

```python
# CORRECT: adapts to the perturbed problem
def match_orange_transceivers(bw: list[int], cap: int) -> list[int]:
    seen = {}
    for i, b in enumerate(bw):
        if cap - b in seen: return [seen[cap - b], i]
        seen[b] = i

# REJECTED (mimicry): correct for L0 but wrong function signature / semantics for L3
def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen: return [seen[target - n], i]
        seen[n] = i
```

The `rejected` sample is the memorized L0 decoy — it **passes** on the original HumanEval problem but **fails** on the perturbed prompt.

## DPO Loss Objective

Implemented in [`trainer.py`](trainer.py) via `trl.DPOTrainer` (Rafailov et al., NeurIPS 2023):

```
L_DPO(θ; π_ref) = -E_{(x,y+,y-) ~ D} [
    log σ( β · log(π_θ(y+|x) / π_ref(y+|x))
          - β · log(π_θ(y-|x) / π_ref(y-|x)) )
]
```

| Term | Value | Description |
|---|---|---|
| `x` | problem prompt (L2/L3/L4 framing) | The perturbed task statement |
| `y+` | chosen response | Structurally correct code + reasoning trace |
| `y-` | rejected response | Memorized L0 decoy that fails on x |
| `π_ref` | frozen reference model | Initial QLoRA adapter before DPO training |
| `β` | **0.1** | KL divergence strength (temperature of preference) |
| `σ` | sigmoid | Converts log-ratio to probability |

**Key property:** With `ref_model=None` in `trl.DPOTrainer` + PEFT, the library automatically computes the reference model's logits by disabling the LoRA adapter — so no second GPU copy is needed.

## Contrastive Pair Construction

The rejected samples are generated by applying one or more of these corruption strategies to the canonical reference solution:

| Corruption Type | Example | What It Tests |
|---|---|---|
| **Off-by-one boundary** | `range(n)` → `range(n-1)` | Whether model catches loop bounds |
| **Variable name permutation** | `target` → `nums`, `seen` → `result` | Lexical vs. semantic reasoning |
| **Conditional branch inversion** | `if a > b` → `if a < b` | Control flow understanding |
| **Return value corruption** | `return [i, j]` → `return None` | Output contract awareness |
| **Wrong entry point** | `def two_sum(...)` on L3 prompt | Function signature mimicry |

## Training Algorithm (Step-by-Step)

```
Data preparation (nb_03_distillation.ipynb):
  1. For each (task_L0, task_L2/L3/L4) pair:
       chosen  = canonical reference solution + CoT trace
       rejected = decoy template (L0 solution applied verbatim to L2+ prompt)
  2. Format as HuggingFace Dataset with columns: [prompt, chosen, rejected]

DPO Training (500 steps):
  1. Load Qwen2.5-Coder-1.5B-Instruct in 4-bit NF4
  2. Attach LoRA adapter (r=16, α=32)
  3. For each batch of (prompt, chosen, rejected):
       a. Forward pass: compute π_θ(y+|x) and π_θ(y-|x)
       b. Reference logits: disable LoRA → compute π_ref(y+|x) and π_ref(y-|x)
       c. Compute DPO loss
       d. Backward + AdamW update
  4. Save checkpoint every 100 steps
  5. Final save at step 500
```

## Scientific Hypothesis

> If explicitly penalizing the model for assigning high probability to structurally-wrong-but-lexically-plausible completions (the L0 decoy), then M3 should show **lower mimicry rates** and **higher generalization** on L2–L4 compared to M2 (vanilla SFT).

**Predicted comparison:** `ΔLadder_AUC(M3 - M2) > 0`, especially on L2 and L3  
**Predicted mechanism:** DPO's KL constraint forces the model to differentiate between the decoy signature and the correct transformed-problem solution.

If M3 underperforms M4 (Standard GRPO), it suggests that **offline contrastive preference learning is weaker than online execution-grounded RL** for anti-mimicry.
